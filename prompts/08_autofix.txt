# 角色
你是一位重視資安的資深 Python 工程師，擅長撰寫自動化腳本。

# 任務
請撰寫一支 Python 腳本 auto_fix.py，放在專案根目錄，功能是讀取 Semgrep 的 JSON 掃描報告，針對每一項發現的問題，呼叫 Gemini API 取得修正後的程式碼，並直接寫回原始檔案。

# 背景
- 專案根目錄有一份 semgrep-results.json，是 Semgrep 用 --json 參數輸出的掃描結果
- 專案已有 generate.py，內含呼叫 Gemini API 的既有邏輯（讀取 .env 中的 GEMINI_API_KEY、AI_MODEL、AI_TEMPERATURE），本次撰寫時可參考其呼叫方式，保持一致

# 技術規格
- 讀取 semgrep-results.json，其中 results 陣列的每一項包含：path（檔案路徑）、start.line 與 end.line（問題所在行號）、check_id（規則名稱）、extra.message（問題說明）
- 針對每一項發現：
    1. 讀取該檔案，取出問題行號前後各 5 行作為上下文
    2. 組成一個 Prompt，內容包含：規則名稱、問題說明、上下文程式碼，明確要求 Gemini「只回傳修正後的程式碼區塊本身，不要任何說明文字、不要 markdown 的 ``` 標記」，且修正範圍應僅限於有問題的那幾行，不可更動上下文其餘程式碼的邏輯
    3. 呼叫 Gemini API 取得回傳的修正後程式碼
    4. 將原始檔案中對應行號範圍的內容，替換為修正後的程式碼
    5. 寫回檔案
- 全部發現處理完後，印出摘要：修正了哪些檔案、哪些規則
- 若 semgrep-results.json 不存在或 results 為空陣列，印出訊息後直接結束，不視為錯誤

# 安全要求
- 不可修改 semgrep-results.json 指定範圍以外的任何程式碼
- 呼叫 Gemini API 時使用的 API 金鑰必須從環境變數讀取，不可寫死
- 若對同一個檔案有多筆發現，需注意處理順序，避免行號替換後互相影響（建議由檔案最後一筆問題往前處理）

- 重要邏輯加上註解
- 若有需要特別說明或提醒之處，列在最後
