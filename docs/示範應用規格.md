# 示範應用規格（階段三）

> 一個「登入 + 商品查詢」的簡易系統，作為方法論的示範範例與六組測試案例的測試標的。
> 架構：前端靜態頁 + 後端 Flask REST API + PostgreSQL，三者各自容器化。
> 設計原則：從六組 TC 反推，做剛好能撐起測試的最小功能，不多做。

---

## 一、功能範圍與測試案例對應

| 功能 | 端點 | 說明 | 對應 TC / 用途 |
|------|------|------|----------------|
| 使用者登入 | `POST /login` | 帳號密碼驗證，回傳登入結果 | **TC-1** SQL Injection 經典目標（登入查詢可被 `' OR '1'='1` 繞過） |
| 商品列表 | `GET /products` | 列出所有商品 | 一般功能 |
| 商品搜尋 | `GET /products/search?q=` | 依關鍵字搜尋商品 | **TC-1** 第二個注入點（搜尋查詢） |
| 新增商品 | `POST /products` | 新增一筆商品（需登入） | 寫入路徑，展示輸入驗證 |

- 密碼以雜湊儲存（`werkzeug` 的 `generate_password_hash`）。
- 用到的 Python 套件列於 `backend/requirements.txt` → **TC-3** SCA 掃描對象。
- 機密（DB 帳密、Flask 密鑰）走 `.env` → **TC-2**。
- TC-4（協作衝突）、TC-5（Prompt 對照）、TC-6（安全部署）屬流程層面，不依賴 app 功能。

## 二、資料模型（PostgreSQL）

### `users`
| 欄位 | 型別 | 說明 |
|------|------|------|
| id | SERIAL PRIMARY KEY | 主鍵 |
| username | VARCHAR(50) UNIQUE NOT NULL | 帳號 |
| password_hash | VARCHAR(255) NOT NULL | 雜湊後的密碼 |
| created_at | TIMESTAMP DEFAULT now() | 建立時間 |

### `products`
| 欄位 | 型別 | 說明 |
|------|------|------|
| id | SERIAL PRIMARY KEY | 主鍵 |
| name | VARCHAR(100) NOT NULL | 商品名稱 |
| description | TEXT | 商品描述 |
| price | NUMERIC(10,2) | 價格 |
| stock | INTEGER DEFAULT 0 | 庫存 |
| created_at | TIMESTAMP DEFAULT now() | 建立時間 |

（商品為共用目錄，與 users 無關聯；登入僅作存取控制與 TC-1 的驗證繞過示範。）

## 四、架構與服務

三個 Docker 容器，由 `docker-compose.yml` 編排：

- **frontend**（nginx）：提供靜態頁，使用者透過瀏覽器存取。
- **backend**（Flask）：REST API，處理登入與商品查詢，連 PostgreSQL。
- **db**（postgres）：資料儲存。

前端與後端是不同來源，後端需設定 **CORS**（用 `flask-cors`）允許前端呼叫。

對應三層架構：瀏覽器 → frontend → backend → db。

## 五、生成順序（逐模組，套用標準 Prompt 範本）

一次只生成並驗證一個模組（模組化指令）：

1. `db.py` + `models.py`（資料層，後面都依賴它）
2. `routes/auth.py`（登入，TC-1 主要目標）
3. `routes/products.py`（列表 / 搜尋 / 新增）
4. `app.py`（組裝、註冊路由、CORS）
5. 前端 `index.html` / `products.html` / `app.js` / `style.css`
6. `Dockerfile`（前後端各一）與 `docker-compose.yml`

每生成一個模組，依方法論文件的 Review Checklist 審查、在沙盒中驗證，通過再進下一個。
